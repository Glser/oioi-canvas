01

目标与方案决策

先复用账户和计价体系，再把画布做成独立的产品入口。

保留现有分组。默认推荐线路。
按需创建、复用用户自己的分组 Key。

Flow 使用 New API 的登录、注册、用户身份、模型权限、价格与调用能力。New API 继续负责渠道选择和结算；Flow 负责创作体验与浏览器本地作品，不新增画布业务数据库。

本期设计目标

  • 独立域名运营，与 New API 共用账户。
  • 登录后读取当前用户可用的模型与线路。
  • 生成前展示所选线路的适用价格或估算。
  • 所有平台模型调用经 New API 鉴权与计费。
  • 画布、素材与生成历史仍由浏览器保存。

能力状态

现有能力 登录会话、用户分组、令牌、渠道路由、模型目录和计价。

建议新增 Flow 受保护目录、应用凭证绑定、固定登录回跳与跨域配置。

待决策 上架分组、默认线路、退出语义、凭证策略及插件开放范围。

本文件是可实施的设计建议；阅读、比较或演示操作不会连接 New API，也不会创建 Key、发起生成或修改项目配置。

“本地保存”的准确含义

画布项目、素材文件和前端历史由浏览器保存；生成时提示词与参考素材仍会经过 New API 和模型供应商。New API 的账户、计费日志及异步任务记录继续保存在服务端，不应宣称请求内容完全不出本机。

04

应用凭证管理

用户无需手工复制 Key；系统必须能明确追踪它属于谁、哪个应用、哪个组。

建议新增 flow_app_token_bindings 绑定记录，把现有 New API Token 与应用用途关联。以下是逻辑字段设计，正式表名和实现按 New API 的现有数据层规范确定。

字段用途约束
user_idNew API 用户身份从服务端认证上下文获取
app_id固定为 flow由集成接口确定，不能任意指定应用
group_id固定调用组标识必须属于用户与 Flow 双方允许的组
token_id关联现有 Token验证归属、状态、组及模型限制
status有效 / 已撤销保留撤销语义，禁止自动复活
created_at / updated_at管理和审计沿用现有时间字段规范
唯一绑定：(user_id, app_id, group_id)
查询目录：只读，不创建 Token
首次调用：验证授权 → 事务内取得或创建绑定与 Token
再次调用：复用有效 Token
切换分组：切换绑定，不修改同一 Token 的 group
显式撤销：标记绑定已撤销，同时禁用关联 Token 并使缓存失效
重新授权：明确授权后，才允许恢复或重新签发

现有令牌名称并不唯一，不能依赖“查找同名 Key，没有就创建”保证幂等。并发首次调用需通过数据库唯一约束、事务与冲突处理保证最终只有一个有效绑定，并避免遗留重复令牌。

绑定策略必须落实到实际推理鉴权。现有 TokenAuth 不会读取新增应用绑定表。撤销绑定时要同时禁用关联 Token 并使令牌缓存失效；下架组、移除模型或收紧上架策略时，同步更新关联 Token 的状态和模型限制，或新增推理入口的应用策略校验。仅修改目录不能收回已签发的调用权限，同步完成前不能宣称新策略已生效。应用管理的组和模型限制还需防止被通用令牌编辑接口绕过；删除或禁用操作应同步绑定状态。

签发规则

  • 按需创建，不为每次登录预建所有组的 Key。
  • 遵守现有令牌数量上限与额度规则。
  • 到达上限时返回可操作错误，不删除其他 Key。
  • Flow 只上架部分模型时，凭证也限制到该模型集合。
  • 失效、禁用、被删除或策略不匹配时，走明确的修复或重新授权流程。

凭证边界

  • 登录 Access Token 与模型 Key 分别管理。
  • 模型 Key 建议仅驻留内存，不进入作品、历史或导出文件。
  • 目录或凭证接口的响应禁止缓存，日志不记录密钥。
  • 上游渠道 Key 只留在 New API，不能返回前端。
  • 新增 Key 不产生额外余额；结算仍归属用户账户。
退出与撤销不是同一件事

现有普通模型 Key 与登录 SID 没有自动绑定。清除 Flow 内存或退出登录，并不使已签发的普通 Key 自动失效。若需要“退出即失效”，必须增加会话关联校验与撤销机制；若按用户和组共享 Key，撤销还会影响使用同一绑定的其他设备。

05

登录与跨域会话

复用 New API 登录页面与会话，不在画布重复实现一套注册系统。

  1. Flow 判断当前身份

    在需要身份时，向 API 域的 POST /api/user/auth/refresh 发起 credentials: include 请求。有效会话返回 Access Token、用户与 session；无有效会话进入登录引导。

  2. 在 New API 完成登录或注册

    使用现有登录、注册、2FA、第三方登录等页面。注册后是否已登录，遵循现有流程；最终取得有效登录会话。

  3. 返回固定的 Flow 回调地址

    建议明确允许 https://flow.oioi.lat/auth/callback。现有同源回跳校验需扩展为受控应用回跳，不允许任意外部地址。URL 不携带 Token 或 Key。

  4. 恢复身份并拉取 Flow 目录

    回调页通过 API 域 Refresh Cookie 恢复身份；模型目录使用内存 Access Token 请求。后续 /api/user/self 可更新账户资料。

  5. 更新本地账户上下文

    用户身份确定后加载对应的 IndexedDB 空间。网络故障不能直接当作匿名；身份变更先隔离旧会话中的请求和缓存。

请求类型凭证要求
刷新 / 退出API 域 HttpOnly Refresh Cookie带 Cookie，启用精确 CORS 与 Origin 校验
用户 / Flow 目录 / 凭证管理登录 Access Token仅内存持有，服务端验证用户权限
模型推理 / 任务查询对应固定组的模型 KeyBearer 请求，默认不携带 Cookie
跨子域接入的四个关键细节
  1. 同站、跨源。两个 HTTPS 子域名可以在请求 API 域时使用其 host-only Cookie，无需把 Cookie 放大到整个 .oioi.lat。带凭据请求必须允许精确 Origin，不能返回通配符来源。
  2. OriginGuard 与 CORS 分别配置。SESSION_COOKIE_TRUSTED_URL 只控制刷新/退出的可信来源，不会自动配置 CORS。预检需要覆盖实际使用的方法和请求头。
  3. Flow 读不到 API 域的 hint Cookie。不能直接照搬“document.cookie 中没有会话提示就跳过 refresh”的优化；身份由服务端判断。
  4. 两域的 Web Locks 和 BroadcastChannel 不共享。刷新冲突与 SID 不匹配应按现有服务端契约恢复；不能承诺两域界面即时同步退出。应在恢复页面、发起受保护操作和收到认证错误时重新确认身份。
退出语义需要产品确认

调用现有 /api/user/auth/logout 会撤销共享登录 SID，也影响 New API 面板。仅清理 Flow 内存只能视为本地退出，之后仍可能由 API 域 Cookie 恢复登录。若要求两站独立登录生命周期，应新增受限的应用会话，而不是把当前共享会话包装成独立退出。

06

模型目录与价格

用户看到的售卖项与最终允许执行的请求，必须使用一致的授权规则。

选择的是“模型 + 线路”。
看到的价格，对应此次调用的组。

Flow 可售卖目录 =
  用户有权使用的调用组
  ∩ Flow 开放的组与模型
  ∩ 已启用且有有效计价配置的模型
  ∩ Flow 支持的能力与协议

执行时再检查：凭证状态、组权限、模型限制与额度
Flow 策略变更：同步 Token 与缓存，或由新增推理鉴权校验

目录查询不依赖事先创建全部 Key。已有绑定时要识别其禁用、撤销或更严格的模型限制；新签发凭证则使用同一套 Flow 策略。前端隐藏选项不构成服务端授权。

现有接口可复用内容注意事项
GET /api/user/self/groups当前用户可用组、说明、适用倍率用于用户维度的组权限；Flow 还需自己的上架白名单
GET /api/user/models?group=…指定可用组的启用模型不能单独反映凭证模型限制与全部计价条件
GET /api/pricing模型说明、分组、价格规则、端点与计价变体公开与否受现有页面配置影响；Flow 集成目录独立要求登录
GET /v1/models该 Key 实际允许的模型集合适合校验已取得的调用凭证；需要模型 Key
GET /api/models按渠道类型组织的模型目录不直接作为用户可调用模型清单

价格展示采用 New API 的规则

  • 使用当前用户在所选组的有效倍率。特殊的“用户组 × 调用组”倍率可覆盖普通组倍率，不能一律重复相乘。
  • 文本分别展示输入、输出等适用单价；实际输出量未知时只做费用估算。
  • 图片和视频按规格、时长、数量及实际计费模式展示；表达式与阶梯计价不能统一简化为一个固定单价。
  • 同组同模型存在不同计价变体时，展示适用变体或范围；无法形成可靠估算时明确说明按实际使用结算。
  • 价格摘要要关联目录版本。版本用于识别变化，不代表锁价承诺；最终以 New API 服务端结算为准。
不要直接复制“最低价”

当前 New API 模型广场在未指定分组时可能取可用组最低倍率展示。Flow 的生成按钮必须依据已经选中的组和参数显示价格，不能展示经济组价格却使用标准组 Key 调用。

已有 supported_endpoint_types 可帮助选择协议，但它不等于完整的参数能力。Flow 需要为上架模型维护明确的尺寸、比例、参考图方式和视频参数能力，未知能力不自动宣称支持。

08

生成与任务归属

选组、定价、凭证、任务和结果，围绕同一次调用绑定。

模型与线路→确认适用价格→取得分组 Key→New API 执行→本地保存结果
  1. 固定本次调用上下文

    记录用户、应用、组、模型、协议、凭证绑定及必要的价格版本。不能在请求途中从全局“当前组”重新读取并改变归属。

  2. 使用对应组的 Key 请求 API 底座

    New API 验证权限、额度、模型可用性，选择渠道并按实际规则计费。标准 /v1 请求不能通过随意附加 group 字段覆盖固定令牌组。

  3. 保存异步任务的必要标识

    有任务 ID 时立即持久化 taskId、发起账户和分组等信息；恢复后使用原归属查询。原凭证失效时先验证重新授权能否访问原任务，不假设所有接口只按用户判断。

  4. 将结果写回发起账户

    用户切换账户或默认线路后，旧任务不会转移归属。关闭浏览器无法保证取消上游执行，恢复时依实际任务协议查询状态。

  5. 把可用媒体下载为本地文件

    成功后保存 Blob 和必要 metadata，不只保存可能过期的远程地址。受保护内容通过对应任务的鉴权接口读取。

本地任务元数据（逻辑结构）
  userId / appId / groupId / modelId / protocol
  credentialBindingId / tokenId / taskId
  status / pricingRevision / localAssetIds

不持久化：Access Token、Refresh Token、模型 Key、上游 Key
失败不等于未扣费

浏览器断线、超时或取消等待，不能单凭客户端状态判定上游没有执行。自动重试付费 POST 请求需要服务端明确支持幂等；本期不新增盲目重试策略。超时、轮询、大小和并发边界沿用已确认设置，新增值须另行确认。

09

本地数据与安全

沿用 localforage / IndexedDB，补齐账号接入后的隔离边界。

本地命名空间 = 平台标识 + New API 用户 ID + 数据类别

  canvas_projects       画布项目与节点
  assets / media_files  素材与媒体 Blob
  generation_history    生成记录与任务归属
  preferences           模型偏好与界面配置

匿名编辑区独立管理；登录后不自动归并到任意账户。

切换账户时切换所有相关 store、查询缓存和媒体引用；退出清除运行时凭证，保留用户自己的本地作品。固定使用 https://flow.oioi.lat 作为入口，替换服务器不影响该源的本地存储；更换域名、协议或端口则属于另一份浏览器存储。

提供导出备份入口，评估持久存储申请，并准确说明浏览器清理与空间回收可能导致数据丢失。账户命名空间是应用层隔离，不等同于针对同一浏览器配置文件访问者的加密保护。

托管版插件是实际的权限边界

现有画布可动态加载远程插件，并通过 new Function 执行模型脚本。它们在同一页面运行时，不能只靠“Token 放内存”隔离账户权限。直接允许 Flow 恢复完整 New API 登录态，会扩大这些脚本可以触及的账户能力。

本期推荐

平台托管版只启用经过审查的内置插件和协议适配代码；应用凭证只允许调用上架组与模型。现有任意脚本/远程插件入口需明确限制后再开放账户接入。

开放插件的后续方案

不可信代码置于独立源沙箱，通过受限消息接口获取宿主能力；不向其提供完整凭证。若需要应用权限进一步收敛，再引入 Flow 专用授权会话与服务端 scope 校验。

仅增加 iframe 标签、仅使用 Worker，或仅不传入 apiKey，都不自动构成充分隔离。沙箱、来源限制、消息契约和可调用动作需要一起设计与验收。

域名与部署

优先拆分静态资源与 API 流量，保留未来调整源站的空间。

flow.oioi.lat
  → HTTPS / Nginx
  → 国内静态服务器：Flow 前端资源

api.oioi.lat
  → HTTPS / Nginx
  → New API：账户、Flow 集成、模型调用

用户浏览器从 Flow 直接请求 API 域。
部署项要求
静态页面SPA 回退到入口文件，包含 /auth/callback；带内容哈希的资源缓存与 HTML 更新策略分别配置
跨域策略账户与集成接口精确允许 Flow Origin；带 Cookie 请求允许 credentials，预检覆盖实际请求头
Cookie / Origin生产使用 HTTPS Secure Cookie；SESSION_COOKIE_TRUSTED_URL 包含实际可信站点，不能将其误当 CORS 配置
缓存用户信息、凭证、刷新和个人化目录禁止共享缓存；CDN 和 Nginx 不缓存密钥响应
流式响应经过的每层代理对对应流式接口关闭响应缓冲；验证内容可持续到达浏览器
回源链路HTTPS 回源验证证书并配置正确 SNI；代理到明确源站，避免回指入口域名造成循环
真实客户端 IP按实际代理链配置 New API 的 TRUSTED_PROXIES，不把任意客户端转发头当可信来源
国内服务器核验实际地域下的 API 可达性、媒体下载、DNS 与证书；部署前确认服务商适用的接入要求
行为边界请求超时、上传大小、并发和重试策略按模型实际需求确认；本方案不静默指定新的数值
如果未来希望所有请求都先经过 Flow 域名

可以由 Flow 的 Nginx 代理一部分 API 路径，但这会改变浏览器看到的请求主机、Cookie 所属与路径、登录回跳及跨域行为。不要假设一条 proxy_pass 就能同时解决单点登录和权限边界。建议第一期保持 API 域直连；确需统一入口时，独立评审 Cookie、Host、Origin 和流式转发策略。

仅托管静态资源不需要画布后端。增加应用绑定与目录配置是在 New API 内扩展集成能力，不会把浏览器作品迁入服务端数据库。

实施与验收

按可验证的业务闭环推进，避免先扩展全部协议再处理账户边界。

阶段 A

确定售卖与权限规则

确认 Flow 上架组、模型、默认线路、价格表述、凭证生命周期及插件范围。对照线上 New API 版本核验本方案引用的接口契约。

阶段 B

打通登录与模型目录

完成固定回跳、精确 CORS、跨源会话恢复、Flow 受保护 catalog 与前端账户上下文。验收已登录复用、注册后返回、无权限模型不可见。

阶段 C

打通文本和图片调用

实现应用凭证绑定、按组按需签发、模型限制及价格展示。贯通生成、计费与媒体本地保存；验证组切换不会修改其他任务的归属。

阶段 D

完善任务与上线环境

逐类适配视频和音频，补齐异步恢复与内容下载；验证国内网络、Nginx 流式响应、撤销、账户切换和本地备份。

验收清单

  • 未登录时受保护目录拒绝访问；New API 登录或注册完成后可以返回 Flow。
  • 已登录用户从 API 面板进入 Flow 能恢复身份；跨源刷新冲突与网络错误不会错误切换账户。
  • 不同用户只看到各自允许的组、模型与适用价格；篡改 group 或 model 不可越权。
  • 首次并发使用同一组只产生一个有效应用绑定；达到令牌上限有明确提示。
  • 同一模型切换线路后，展示组、凭证组、实际计费组一致；不默认跨组涨价。
  • 凭证被撤销不会自动重建；退出行为与已确认的产品语义一致。
  • 切换账户后，旧任务的查询、结果与素材仍归属原账户。
  • 视频任务恢复按原协议与归属执行；重复点击和断线不触发无条件付费重试。
  • 作品可在重新打开页面后读取，导出中不包含 Token 或 Key。
  • 所有流式代理链路、媒体下载与国内真实网络可用性通过联调。
  • 托管版插件权限符合选定策略，第三方代码不能获得未授权的账户能力。

本清单用于后续实现验收，当前未标记任何一项为已通过。方案整理本身不改变功能与待办状态。
