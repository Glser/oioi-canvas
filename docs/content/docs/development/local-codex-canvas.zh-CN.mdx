# 本地 Agent 连接画布原理

当前源码采用「网页对话 + npm CLI 本地服务 + 原生 Agent 运行时」。首版接入 Codex；不新增桌面客户端，不自行实现 Agent 推理循环。新版 npm 包尚未发布，当前使用仓库 `canvas-agent` 的开发入口，实际运行验收见待测试清单。

## 双向调用链

```text
首页 / Agent 对话面板
  -> 本机 HTTP 会话接口
  -> codex app-server（stdio JSON-RPC）
  -> 原生会话、工具执行及审批
  -> SSE agent_state
  -> 网页展示回复、进展及确认请求

Codex 调用受管画布 MCP
  -> POST /api/agent/tools
  -> SSE tool_call（固定 clientId / expectedProjectId）
  -> 浏览器画布 React 状态
  -> POST /canvas/result
  -> MCP 工具结果
```

网页不直接启动本地进程。用户需在同一台电脑上安装并启动 CLI，以及安装、完成认证的 Codex。服务保持前台运行；关闭终端会中断连接。无需手动注册受管会话的 MCP，也无需复制业务需求。

## 连接与首页提交

本机服务默认监听 `http://127.0.0.1:17371`，通过配对码换取连接 token。线上网站也由浏览器直连本机，不经过项目后端或内网穿透；另一台设备的 loopback 不指向这台电脑。浏览器要求本地网络权限时须由用户确认。

首页输入创建画布，并把带唯一提交标识的需求保存到浏览器 localforage。连接完成后，先上报目标画布状态，再创建或恢复会话，随后自动提交。侧栏支持继续对话、工具进展、命令/文件/权限确认、结构化问题及停止执行。

服务连接状态与 Codex 会话状态分开显示。运行时缺失、认证失败或协议不支持时展示错误并保留需求，修复后手动恢复会话；不会自动安装或升级 Agent。

## 自动发现与配置复用

CLI 查找系统 PATH/PATHEXT 下的 Codex、Claude Code、CodeBuddy、OpenCode，并读取版本；自动检测不等于执行适配，目前网页只接入 Codex，其他已安装工具明确标为尚未适配。

配对后通过原生 `config/read`、`model/list`、`skills/list`、`mcpServerStatus/list` 读取能力。配置默认值与会话实际生效值分开呈现；只向网页返回必要字段，不回传原始配置、环境变量或凭证。模型目录失败时保留当前配置，不自行生成候选模型。

网页自动探测服务，首次授权后可在 CLI 重启时恢复连接；用户主动断开时暂停自动连接。运行时检测结果使用 localforage 缓存，服务离线时仅作历史状态展示。

## 会话接口

以下接口需要连接 token；会话操作还校验已连接网页的来源、clientId 与当前 projectId：

- `GET /agent/runtimes`：读取自动检测的机器和运行时，`refresh=true` 可重新检测。
- `GET /agent/runtime-info`：无需新建对话即可读取 Codex 本机默认能力，仅返回经过筛选的字段。
- `POST /agent/capabilities`：刷新当前会话的配置、模型目录、Skills 和 MCP 信息。
- `POST /agent/connect`：创建或恢复当前画布会话。
- `POST /agent/send`：使用 submissionId 提交一轮输入，可带原生目录中的 model / reasoningEffort；默认不覆盖运行时选择。
- `POST /agent/answer`：回传批准、拒绝或问题回答。
- `POST /agent/interrupt`：请求中断当前 turn，不代表撤销已执行的画布或外部生成操作。
- `GET /events`：复用 SSE，分别发送 `agent_state` 与 `tool_call`。
- `POST /canvas/state`、`POST /canvas/result`：继续承担画布快照与工具结果。

网页通信协议为 `9`，与会话映射清单的版本独立管理。

## 目标与权限

每个网站来源下的画布关联一个原生 thread。受管 MCP 的目标由本地服务固定；不暴露重新绑定工具，运行中的会话不能被其他标签页夺取。网页换画布、断开或返回错误目标时拒绝工具调用，不静默切换到最近焦点页。

新会话使用启动 CLI 时的目录；原生会话恢复时保留已记录的目录。网页不能任意指定可执行程序或工作目录。受管会话默认沿用原生模型、权限与指令，不再覆盖 sandbox/approvalPolicy。网页回显实际生效值；原生配置已关闭部分保护时明确提示，不替用户静默放宽权限。受管 MCP 配置只作用于该会话，不写入用户全局 Agent 配置。

尚未实现的原生交互明确拒绝并显示原因。网页接收到已授权的画布工具后执行操作，不另造一套重复的画布审批。

## 历史与恢复

Codex 保管原生正文历史。本地 `~/.oioi-canvas/conversations.json` 只保存网站/画布到 thread 的映射、工作目录和提交回执；未知版本、损坏内容或外部修改拒绝覆盖。没有数量或体积裁剪，也没有旧格式静默迁移。

实时消息同时按 threadId、turnId、itemId 归属。完整原生历史成为权威后，不再重复合并对应 turn 的实时事件；完成通知没有加载 items 时，读取原生条目后替换，不把空通知当作空历史。

发送前记录提交标识，已接收的提交不会再次执行。连接中断导致接收状态不确定时，先检查历史，不自动重放；同一提交的重试继续使用原标识。网页关闭时画布工具不可用，后台 Agent 仍运行不代表能完成画布操作。

画布项目与「我的素材」仍主要保存在浏览器本地；此能力不提供云同步。内容会交给所选 Agent 及其模型服务，画布生成仍使用原有前端生成接口与凭证。

## 独立 MCP 模式

保留原生 Codex / Claude Code 直接操作画布的入口：`canvas-agent mcp`。该进程读取同一份本机服务配置，通过 `/api/tools` 调用桥接；对话继续留在原生界面。

独立模式每个 MCP 进程有自己的 bindingId，业务工具前需要 `canvas_list_clients` 和 `canvas_bind_client`，结束时可 `canvas_release_client`。安装 MCP 不代表已经启动 HTTP 服务。不要重复安装已有插件提供的同名 MCP。
